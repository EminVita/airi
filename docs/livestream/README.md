# 文字直播排练

我可以先用文字排练一场 30 分钟的直播，随时扮演观众发弹幕。排练沿用当前角色的文字模型，不调用语音合成，也不播放音频。

## 我维护哪三份文件

我长期保留 Soul 和直播规则，只在每次开播前修改当天主题。

| 文件 | 修改时机 | 内容与作用 |
| --- | --- | --- |
| [soul.md](../../packages/stage-ui/src/constants/prompts/soul.md) | 长期身份或表达方式需要调整时 | 我的长期性格、表达、事实边界和临时扮演原则。与当前角色卡一起进入普通聊天、主动通知和直播 |
| [livestream-rules.md](../../packages/stage-ui/src/libs/livestream/prompts/livestream-rules.md) | 直播工作方式需要调整时 | 每场都遵守的接弹幕、续讲、转题、计时、内容边界和表达检查规则 |
| [episode.md](episode.md) | 每次开播前 | 当天主题、临时角色、固定情节、分段安排、资料和结束位置。当前已填好“林冲风雪山神庙” |

前两份由程序自动加载，不需要每次导入。第三份通过“导入本场 Markdown”读入，或直接粘贴进“本场内容”。文件名可以更换。

林冲这一场的“直播主线”填写：`林冲风雪山神庙：我原想熬过这个冬天`。模式选择“文字排练 · 30 分钟”。

AIRI 原有的角色卡保存名字、背景、性格和系统提示词。Soul 接在这个共同入口，普通聊天和直播读取同一份身份。当天扮演林冲不会改写角色卡或 Soul。

这个共同入口覆盖使用 Stage UI 的桌面、Web 和移动端角色功能。独立的 Minecraft、Telegram 等集成有自己的提示词入口，目前不读取这份 Soul。

普通聊天还使用原有的记忆、工具和舞台控制规则。直播只复用角色身份，再加入直播规则，不带入普通聊天的动作标记或工具指令。

Soul、直播规则和“好好说话”正文使用 Vite 原文导入。修改后需要重新构建并重启应用。当天主题只需重新导入，不用构建。磁盘上的文件变更不会修改正在进行的直播。

我可以参考[空白主题模板](../../packages/stage-ui/src/libs/livestream/prompts/episode-template.md)或[校园故事示例](episode-campus.md)。它们都是第三类文件的示例，不是额外的常驻配置。

`AGENTS.md` 管的是 Codex 修改项目时的行为，AIRI 的模型不会自动读它。Markdown 只有通过上述入口加载，才会进入模型请求。

## 我怎样排练

打开桌面聊天窗口，展开“自主直播”。选择“文字排练 · 30 分钟”，填写主线和本场内容，再点击“开始 30 分钟文字排练”。

我在“模拟观众昵称”和“模拟弹幕”中输入内容，点击“发送弹幕”。换一个昵称，就能扮演另一位观众。这里和普通聊天输入框分开，普通聊天会暂停自主循环。

每次显示完整的一句，按约每分钟 220 字加句末停顿留出阅读时间。同时准备下一句，优质弹幕可以替换还没显示的内容。AI 会筛选弹幕，不保证逐条回应。

我可以暂停、继续，或者输入新的方向。文字已经显示出来时，暂停会保留这句的进度。等待模型的时间计入排练，暂停的时间不计入。约 30 分钟到时，程序停止生成和展示，不等待失去响应的请求。

排练最后两分钟会提示模型收束，最后半分钟简短告别。这是生成规则，具体叙事效果需要回看确认。模型返回格式错误或服务连续失败三次时，排练会暂停并显示原因。

## 我怎样看效果

“排练记录”按最新在前显示，默认显示最近 30 条。可以展开全部，也可以点击“复制记录（Markdown）”，粘贴保存成文件。记录包括收到的弹幕、实际展示的句子、对应回复和运营者调整的方向。

我回看时主要检查：能不能听懂前后关系，是否回答了弹幕的意思，接话后是否还记得故事位置，有没有重复句式或强行总结。发现问题后，优先修改本场内容或口吻规则，再做下一轮排练。

记录目前保存在内存中，最多保留最近 5000 条。普通 30 分钟排练通常远少于这个数量。开始新一场、重载角色主窗口或退出应用前，先复制保存需要保留的记录。只收起控制面板不会停止循环。

## “好好说话”怎样生效

项目保留了[技能正文](../../packages/stage-ui/src/libs/livestream/prompts/haohao-shuohua/skill.md)和附带参考文件。技能是直播规则自动使用的固定资料，不是每场要填写的第四份配置。

每次直播生成都发送共同角色身份、技能正文、直播规则和本场内容。参考文件用于维护和查阅，没有逐份发送。普通聊天共用 Soul，不加载直播规则或当天主题。

生成请求要求先形成一句话，再结合上下文检查事实、重复、用词和节奏，然后返回最终句子。检查不另开一次模型调用。技能中用于飞书发布、命令行扫描和修改报告的步骤不在实时直播中执行。

原创故事允许补充情节，但固定设定和已讲出的事实必须保持一致。指定文学原作时，还要保留原作关键事件和结局。模型是否每次都写得自然仍需通过排练检查，不能靠提示词保证。

文字排练仍消耗当前文字模型的额度。完整技能正文会增加输入上下文，这轮没有增加评分服务或语音费用。
