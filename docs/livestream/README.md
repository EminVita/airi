# 文字直播排练

我可以先用文字排练一场 30 分钟的直播，随时扮演观众发弹幕。排练沿用当前角色的文字模型，不调用语音合成，也不播放音频。

## 开播前我准备什么

每场只需准备一份 `episode.md`。文件名可以更换，内容直接粘贴进“本场内容”，或者通过“导入本场 Markdown”选择文件。

| 文件 | 我填什么 | 程序怎样使用 |
| --- | --- | --- |
| [episode-template.md](../../packages/stage-ui/src/libs/livestream/prompts/episode-template.md) | 我的角色、固定细节、分段安排、创作范围和禁讲内容 | 复制成自己的 `episode.md`。开播后，全文随每次文字生成发送 |
| [host.md](../../packages/stage-ui/src/libs/livestream/prompts/host.md) | 长期使用的主播口吻 | 构建时载入，每次生成作为系统规则发送。默认第一人称、自然口语 |
| [workflow.md](../../packages/stage-ui/src/libs/livestream/prompts/workflow.md) | 怎样接弹幕、续讲、转题和收尾 | 构建时载入，每次生成作为系统规则发送 |
| [好好说话正文](../../packages/stage-ui/src/libs/livestream/prompts/haohao-shuohua/skill.md) | 已从当前 Codex 技能复制，无需每场填写 | 正文完整加入每次直播生成的系统提示，要求在同一次生成内检查用词和节奏 |

[校园故事示例](episode-campus.md)已经填好，可以先用它熟悉操作，再换成我的内容。模板中的时间安排只是叙事参考。程序负责实际计时。

`host.md`、`workflow.md` 和技能正文使用 Vite 的原文导入。修改这些源码文件后，需要重新构建并刷新应用。编辑磁盘上的 `episode.md` 不会改变已经开始的直播，下一次开播前重新导入即可。

`AGENTS.md` 管的是 Codex 修改项目时的行为。把主播要求只写进 `AGENTS.md`，不会让 AIRI 的模型自动读到。本功能在 `prompt.ts` 中明确载入上述规则，在直播 host 中随每次请求发送。

## 我怎样排练

打开桌面聊天窗口，展开“自主直播”。选择“文字排练 · 30 分钟”，填写主线和本场内容，再点击“开始 30 分钟文字排练”。

我在“模拟观众昵称”和“模拟弹幕”中输入内容，点击“发送弹幕”。换一个昵称，就能扮演另一位观众。这里和普通聊天输入框分开，普通聊天会暂停自主循环。

每次显示完整的一句，按约每分钟 220 字加句末停顿留出阅读时间。同时准备下一句，优质弹幕可以替换还没显示的内容。AI 会筛选弹幕，不保证逐条回应。

我可以暂停、继续，或者输入新的方向。文字已经显示出来时，暂停会保留这句的进度。等待模型的时间计入排练，暂停的时间不计入。约 30 分钟到时，程序停止生成和展示，不等待失去响应的请求。

排练最后两分钟会提示模型收束，最后半分钟简短告别。这是生成规则，具体叙事效果需要回看确认。模型返回格式错误或服务连续失败三次时，排练会暂停并显示原因。

## 我怎样看效果

“排练记录”按最新在前显示，默认显示最近 30 条。可以展开全部，也可以点击“复制记录（Markdown）”，粘贴保存成文件。记录包括收到的弹幕、实际展示的句子、对应回复和运营者调整的方向。

我回看时主要检查：能不能听懂前后关系，是否回答了弹幕的意思，接话后是否还记得故事位置，有没有重复句式或强行总结。发现问题后，优先修改本场内容或口吻规则，再做下一轮排练。

记录目前保存在内存中，最多保留最近 5000 条。普通 30 分钟排练通常远少于这个数量。开始新一场、重载角色主窗口或退出应用前，先复制保存需要保留的记录。只收起控制面板不会停止循环。

## “好好说话”怎样生效

项目保留了技能正文和附带参考文件。每次直播生成都发送正文、主播口吻、工作流和本场内容。参考文件用于维护和查阅，没有逐份重复发送。普通聊天仍使用原有角色配置。

生成请求要求先形成一句话，再结合上下文检查事实、重复、用词和节奏，然后返回最终句子。检查不另开一次模型调用。技能中用于飞书发布、命令行扫描和修改报告的步骤不在实时直播中执行。

原创故事允许补充情节，但固定设定和已讲出的事实必须保持一致。技能规则已接入请求，模型是否每次都写得自然仍需通过排练检查，不能靠提示词保证。

文字排练仍消耗当前文字模型的额度。完整技能正文会增加输入上下文，这轮没有增加评分服务或语音费用。
